0. 범용 PRD의 역할

이 문서는 구현 기술의 목록이 아니라, 앞으로 만드는 모든 미래추론 Domain PRD의 설계 헌법과 작성 Template이다.

각 Domain PRD는 이 문서와 동일한 번호를 사용한다. 범용 문서가 왜와 무엇을 규정하면, Domain 문서는 같은 항목에서 실제 Entity, Factor, Module, Data, Graph, API, 화면, 계산, 검증 방법을 정의한다.

Part 1. Why — Domain 문제 정의 원칙

1-1Vision인간이 왜 이 문제를 충분히 예측하지 못했는지, AI가 기억·계산·학제간 통합 한계를 어떻게 보완할지를 정의한다.
1-2Core Hypothesis관측 가능한 Factor, 상호작용, 시간지연, 행위자 행동을 충분히 기억하고 추론하면 기존보다 유용한 확률예측이 가능한지를 검증 가능한 가설로 만든다.
1-3Prediction Objective예측대상, Horizon, 출력형태, 의사결정 목적을 명시한다.
1-4Limits완벽한 예측은 주장하지 않는다. Unknown Unknowns, Reflexivity, 구조적 단절, 전략적 기만을 확률과 Confidence에 반영한다.

Part 2. World Model — 현실 표현 원칙

범용 역할 분담
2-1Existing Knowledge as Building Blocks기존 통계, 경제학, 게임이론, 시나리오, 시스템 시뮬레이션을 나열하지 않는다. 각 추론기능을 구현하기 위해 필요한 부분만 사용한다.
2-2Ontology & Knowledge GraphOntology는 Entity와 관계의 의미체계를 정의한다. Ontology 자체는 확률적 예측기가 아니므로 실제 Fact, Evidence, Edge 방향·강도·Confidence·Time Lag·Regime은 Knowledge Graph와 별도 인과·확률 계층에서 관리한다.
2-3Causal World ModelEntity, Factor, State, Event, Cause, Effect, Interaction, Feedback, Outcome을 표현한다.
2-4Modular Decomposition거대한 Black Box를 인과영역별 Module로 분해하고 각 Module은 Input, State, Output, Confidence, Update Frequency를 가진다.
2-5Factor & TimeDirection, Importance, Leading/Lagging, Lag, Duration, Acceleration, Decay를 정의한다.
2-6Interaction & Unknowns비선형 상호작용, Feedback, Threshold, Regime Change를 허용하고 설명되지 않는 오류에서 Missing Factor를 추가한다.

Part 3. Data & Memory — 기억 원칙

3-1Continuous Data각 Module이 Raw/Processed Data, Source, Timestamp, Confidence, Revision History를 지속 저장한다.
3-2Fact VerificationFact와 Opinion을 분리하고 Source hierarchy, Cross-validation, Conflict를 관리한다.
3-3Long-Term MemoryLLM 자체 기억이 아니라 Time-Series DB, Relational DB, Knowledge Graph, Prediction Journal, Learned Experience를 외부 기억으로 사용한다.
3-4Prediction Journal예측 당시 Data version, Graph version, Module State, Probability, Confidence, 찬반 Evidence를 Snapshot으로 고정한다.

Part 4. Reasoning & Simulation — 추론 원칙

4-1Current State먼저 각 Module의 State, Direction, Momentum, Regime, Confidence를 추정한다.
4-2Causal Reasoning복수 원인, 상쇄·증폭, Feedback을 추적 가능한 Graph로 전파한다.
4-3Scenario & SimulationBase/Upside/Downside/Tail Risk와 What-if/Counterfactual을 제공한다.
4-4Probability새 Evidence로 확률을 Update하며 특정 알고리즘 하나에 종속되지 않는다.
4-5Explainable Probability왜 65%인지, 왜 80%나 50%가 아닌지 Module/Factor/Interaction/Historical Experience의 기여로 설명한다.
4-6What Would Change My Mind?판단을 뒤집는 Trigger와 재계산 결과를 사전에 보여준다.
4-7ChallengerAI와 인간의 Main Hypothesis를 모두 반대 Evidence로 검증한다.

Part 5. Review & Learning — 학습 원칙

지속 학습 폐쇄루프
5-1Actual Outcome결과와 중간 Factor 변화를 기록한다.
5-2Human + AI ReviewFactor, Direction, Weight, Lag, Interaction, Missing Factor, Regime을 분해 검증한다.
5-3Learned Experience검증된 교훈을 Evidence-linked Experience로 저장한다.
5-4Anti-OverfittingSimilarity, Recency, Sample Size, Regime Match, Source Reliability로 과거 경험의 적용을 제한하고 이번 확률에 미친 영향을 공개한다.
5-5Continuous ImprovementAccuracy뿐 아니라 Calibration과 Explanation Quality가 시간에 따라 개선되는지 측정한다.

Part 6. Domain PRD Template — 구현 문서가 반드시 포함할 것

항목Domain PRD에서 구체화할 내용
6-1 Modules실제 Module 명, Input, State, Output, Update Frequency, Dependency.
6-2 Data Architecture실제 DB, table/schema, graph node/edge, ingestion, retention.
6-3 API/OrchestrationAgent/Job/API contract, orchestration 순서, failure/retry.
6-4 UIHigh-resolution System Map, Module drill-down, Factor detail, Scenario mode.
6-5 DevOpsGit repository, branches, migrations, CI/CD, secrets, staging/production.
6-6 ValidationBacktest, Forward Test, calibration metric, acceptance criteria.
새 Domain PRD는 이 Template을 복사해 같은 번호에서 구체 구현을 채운다. 범용 원칙은 Domain의 편의를 위해 삭제하지 않는다.
